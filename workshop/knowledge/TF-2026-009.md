# Review: tests that pass for the wrong reason

A review of the order tests after release 2.2.0 found assertions that cannot fail when the feature is broken:

- Pagination test asserts `len(orders) == 20`. It would pass if the endpoint returned any 20 orders.
- Discount tests use 100.00 and 200.00. No odd cents, no rounding boundary.
- No invoice test contains an order with a removed item (the feature arrived later, in 2.3.0, and the invoice
  tests were not revisited).
- No test compares the invoice total with the order total for the same order after an item changed.

Recommendation: for every list endpoint assert the first and last id of a page; for every money calculation
add a case at x.5 of a cent; when a feature changes what "counts", add a case to every consumer of that data.

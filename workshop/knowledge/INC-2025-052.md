# Deploy locked the orders table for nine minutes

## What happened
A migration that ran in the afternoon deploy window blocked all writes to `orders` for nine minutes. Checkout
returned errors for that time.

## Root cause
Two statements in one migration: a plain `CREATE INDEX` on a large table, which blocks writes until the index is
built, and `ALTER TABLE ... ADD COLUMN ... NOT NULL` without a default, which failed on the existing rows after
holding an exclusive lock, so the whole migration was retried.

## Lessons
- On PostgreSQL build indexes on large tables with `CREATE INDEX CONCURRENTLY`, outside a transaction.
- Add new columns as nullable (or with a constant default), backfill in batches, then add the NOT NULL constraint.
- During a rolling deploy the old application version is still running. A new NOT NULL column that the old
  version does not write makes its INSERTs fail.
- Every migration needs a tested way back.

# Payments screen timed out after a table rebuild

## What happened
After release 1.9.0 the payments screen in the admin console timed out for large merchants. Latency went from
30 ms to more than 6 s.

## Root cause
Migration 0031 rebuilt the `payments` table (create new table, copy rows, drop old, rename) to change a column
type. Indexes belong to the table that is dropped. The migration recreated the primary key but not the secondary
index on `(merchant_id, created_at)`, so every lookup became a sequential scan followed by a sort.

## Fix
Recreated the index with `CREATE INDEX CONCURRENTLY`. Latency returned to normal within a minute.

## Lessons
- A table rebuild silently drops every index, trigger and grant that is not recreated by hand.
- Compare the list of indexes before and after every migration that rebuilds a table.
- "We did not change that endpoint" does not mean the release did not change its query plan.

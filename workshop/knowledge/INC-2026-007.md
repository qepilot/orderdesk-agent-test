# Nightly export skipped the first batch of records

## What happened
The nightly export to the warehouse was missing the 500 most recent records every night for three weeks.

## Root cause
The export reads in batches. A refactoring changed the batch counter to start at 1 but kept computing the
starting row as `batch_number * batch_size`. The first batch therefore started at row 500 and rows 0-499 were
never read. Nothing failed: every batch had the expected size.

## Lessons
- Counters that start at 1 need `(n - 1) * size`.
- A test that only checks how many rows come back cannot detect that they are the wrong rows. Assert on
  the identity of the first and last row.
- Sorting by a column that is not unique makes batch boundaries unstable; add the primary key as a tiebreaker.

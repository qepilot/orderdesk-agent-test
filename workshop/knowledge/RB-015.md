# Checklist for schema migrations

- Indexes on large tables: `CREATE INDEX CONCURRENTLY`. Plain `CREATE INDEX` blocks writes.
- New column: nullable or with a constant default first; backfill in batches; add NOT NULL afterwards.
- One large `UPDATE` of every row holds locks and bloats the table. Batch it.
- Rolling deploys: the previous application version must work against the new schema (expand, then contract).
- Table rebuilds: list indexes, constraints, triggers and grants before and after.
- Composite index column order: equality columns first, then the ORDER BY column.
- Every migration ships with a down migration and was run against a copy of production data.
- Never run a risky migration in the business-hours deploy window.

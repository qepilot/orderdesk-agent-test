# Refund amounts included soft-deleted line items

## What happened
Between 2025-09-02 and 2025-09-13, 212 refunds paid back more money than the customer had been charged.

## Root cause
The refunds module summed rows of `order_items` without checking whether a row was still part of the order.
Line items that had been soft-deleted by the returns flow were added to the refund amount. The order screen
used a different query that skipped them, so support staff saw the right number and the payout was wrong.

## Fix
Added the missing row filter to the refund query and a test with a soft-deleted line.

## Lessons
- Any code that adds up `order_items` must exclude rows that no longer count. Two modules computing the same
  total with two different queries will drift apart sooner or later.
- When a total is wrong, look for a second code path that computes "the same" number.
- After fixing the code, the rows already written are still wrong. Count them and plan the correction separately.

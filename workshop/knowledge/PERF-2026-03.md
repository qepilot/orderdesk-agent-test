# "My orders" page issues one query per order

Tracing `GET /customers/{id}/orders` shows 1 query for the list of orders and then 3 more per order (items, then items and
discount code again for the total), 61 statements for a page of 20 orders.

Each statement is fast (under 1 ms with the right index), so the page is acceptable today. It will degrade
linearly with page size and badly if any of the per-order statements loses its index.

Recommendation: load the items of all orders on the page with one `WHERE order_id IN (...)` query. Low priority.
